# AutoparkDB — курсовой проект по СУБД

Проект автопарка на **ASP.NET Web Forms / C# / ADO.NET / SQL Server (T-SQL)**. Приложение рассчитано на .NET Framework 4.6.1.

## Состояние репозитория

Этот репозиторий хранит исходный код курсового проекта, но не является готовым переносимым стендом с базой данных. Рабочая база на компьютере разработчика и SQL-скрипт, закоммиченный в Git, могут отличаться: файл ниже был восстановлен из локальных файлов и не синхронизирован с более поздними изменениями в экземпляре SQL Server.

### Важно о SQL-скрипте

`BRU.WEBFORMS.ASPNET.APP/Data/AutoparkDB_Schema.sql` — историческая копия сценария создания/сброса базы, **не канонический скрипт развёртывания актуального состояния БД**.

Скрипт содержит разрушительную последовательность: переводит существующую `AutoparkDB` в `SINGLE_USER` с принудительным откатом подключений и затем удаляет базу через `DROP DATABASE`. Не запускайте его против базы с нужными данными. Наличие файла в репозитории не означает, что он был успешно проверен как чистая установка или полностью отражает текущее состояние рабочей БД.

В Git не хранится резервная копия рабочей базы и не публикуются учётные данные подключения. Восстановление актуальной БД должно выполняться по отдельному, проверенному экспорту именно нужного экземпляра SQL Server, а не предполагаться по этому историческому файлу.

### Корректирующий SQL-патч

`BRU.WEBFORMS.ASPNET.APP/Data/AutoparkDB_ConsistencyPatch.sql` содержит исправления триггеров и отчётных объектов для схемы существующей БД, зафиксированной экспортом от **11 октября 2026 года**. Это дополнительный патч, а не скрипт создания базы. Он не совместим автоматически с историческим `AutoparkDB_Schema.sql`: сначала необходимо подтвердить, что целевая база содержит ожидаемые объекты. Перед запуском сделайте резервную копию и проверьте скрипт.

Патч исправляет обработку отменённых/возвращённых продаж в остатках билетов и отчётности, удаляет дублирующий триггер оплаты, согласует правила статуса автобуса при пробеге от 250 000 км и синхронизирует статус продажи с полной оплатой. Процедуры продажи/оплаты дополнительно проверяют статус рейса, наличие мест, активность билета и возможность принимать оплату; остаток свободных мест пересчитывается после продажи. Синхронизация автобуса с ТО работает после вставки, изменения и удаления записи. Пограничная дата в фильтре продаж тоже исправлена. В C#-отчёте отменённые продажи не учитываются в валовой выручке. Патч также идемпотентно пересчитывает статусы продажи/оплаты по суммам успешных платежей, кэш свободных мест и производные пробег/статус автобусов по истории ТО. Триггеры продаж поддерживают кэш свободных мест при вставке, изменении статуса/количества и удалении продажи. Исторические остатки типов билетов патч не пересчитывает: исходное количество запасов неизвестно, а слепое добавление отменённых продаж при повторном запуске завысило бы остаток. Обновлённая версия патча была выполнена пользователем на целевой БД 11 октября 2026 года без показанных ошибок SQL Server. Клиент сообщил итоговые счётчики: 60 затронутых строк продаж, 320 расписаний, затем два обновления по одной строке для состояния автобусов. Эти счётчики подтверждают выполнение соответствующих UPDATE, но сами по себе не доказывают корректность всех бизнес-сценариев. Интеграционные проверки БД в CI отсутствуют.

## Сборка и проверка

Workflow GitHub Actions `.github/workflows/build.yml` выполняет восстановление NuGet-пакетов и сборку проекта через MSBuild на Windows. Успешная сборка подтверждает компиляцию, но **не** подтверждает запуск приложения, доступность SQL Server, корректность строки подключения или выполнение хранимых процедур, триггеров и курсоров.

Для локальной проверки нужны Windows, Visual Studio с инструментами ASP.NET/Web Forms, targeting pack .NET Framework 4.6.1 и доступный экземпляр SQL Server с настроенной базой. Перед запуском проверьте параметры подключения в локальной конфигурации `Web.config`. Не добавляйте пароли и иные секреты в Git.

## Технические ограничения

- Приложение использует существующую конфигурацию SQL Server; готовая универсальная среда запуска в репозитории не поставляется.
- CI пока не запускает SQL Server и не выполняет интеграционные тесты с базой.
- Игнорирование сгенерированных файлов настроено через `.gitignore`. Уже отслеживаемые Git файлы не удаляются автоматически этим правилом.
